# پایلوت دستیار مکالمه FXGuard

مالک: Ersan Jahed Tabrizi — `docs/AUTHOR.md`

## یافته بررسی اتصال موجود

`lib/aiChat.js` از axios و endpoint چت OpenAI استفاده می‌کند. انتخاب سرویس و کلید در
`lib/aiProviders.js` است؛ اتصال قدیمی در `services/incomingMessage.js` می‌تواند خروجی
`aiResponseService` را از طریق `sendAutoReply` به واتساپ بفرستد. این بررسی کد است؛
فعال‌بودن کلید، اعتبار/بودجه حساب production یا صحت خروجی مدل زنده تأیید نشده است.

## رفتار جدید

- دو عمل در مکالمه: پیش‌نویس پاسخ و خلاصه داخلی، به درخواست کارمند مجاز.
- حداکثر ۳۰ پیام اخیر / ۱۲هزار کاراکتر متن، خروجی حداکثر ۶۰۰ توکن؛ بدون پیوست.
- متن مکالمه فقط داده است؛ هیچ ابزار اجرایی به مدل داده نمی‌شود.
- تولید هیچ Message خروجی، ارسال WhatsApp یا تغییر اطلاعات مشتری ایجاد نمی‌کند.
- پیش‌نویس قابل ویرایش است. فقط دکمه تأیید کارمند آن را در کادر پاسخ می‌گذارد؛
  دکمه معمول ارسال، عمل جداگانه کارمند است. خلاصه به کادر پاسخ منتقل نمی‌شود.
- درخواست ارسال دارای `aiAssisted:true` بدون `aiReviewConfirmed:true` رد می‌شود.
  این فیلد به‌تنهایی اثبات حضور انسان نیست؛ مرز اصلی، نبود ارسال در مسیر تولید و
  اقدام صریح کارمند در UI است. ارسال دستی فعلی همچنان در اختیار کارمند مجاز است.
- تعویض مکالمه/خروج، نتیجه در حال انتظار را باطل و خروجی بازبینی را پاک می‌کند.
- کلید همان سازمان برای OpenAI به‌صورت صریح انتخاب می‌شود؛ fallback به Claude یا
  سرویس دیگر انجام نمی‌شود. پنل‌های SaaS کلید env سکو را قرض نمی‌گیرند.
- مجوز بخش مکالمات و مرز سازمان/مکالمه پیش از خواندن پیام و پس از درخواست مدل بررسی
  می‌شود. پاسخ‌ها `no-store` هستند. audit شامل نوع عملیات و شناسه‌هاست، نه متن یا کلید.
- سقف شش تولید در دقیقه برای هر کارمند/سازمان؛ شمارنده در حافظه هر پردازه است.
  در نصب چندپردازه، سقف تجمیعی بزرگ‌تر است؛ بودجه سخت را روی پروژه OpenAI هم تنظیم کنید.

## فعال‌سازی محدود توسط اپراتور

پیش‌فرض خاموش است. این PR انتشار یا فعال‌سازی production نیست.

```env
AI_ASSISTANT_PILOT_ENABLED=true
AI_ASSISTANT_PILOT_PANELS=t-your-test-panel
```

مقدار دقیق `panelKey` سازمان آزمایشی را استفاده کنید؛ شناسه حدس نزنید. برای پنل legacy
سکو کلید `default` است. نبود allowlist فقط `default` را شامل می‌شود؛ wildcard وجود ندارد.
کلید OpenAI را در تنظیمات همان سازمان تنظیم کنید. فقط برای سکو env موجود قابل استفاده است.
در پنل‌های عضو پایلوت، **AI خودکار قدیمی متوقف می‌شود**؛ بیرون allowlist رفتار قدیمی حفظ
می‌شود. این تغییر پیام‌های قالبی مستقل مثل خوش‌آمدگویی را خاموش نمی‌کند.

ابتدا staging و داده ساختگی: پیش‌نویس → ویرایش → تأیید برای کادر پاسخ → ارسال دستی.
برای آزمون واقعی کلید/مدل، اپراتور باید حساب و بودجه API را بررسی کند؛ در آزمون‌های این
تغییر هیچ داده واقعی، درخواست پولی OpenAI یا پیام واقعی WhatsApp ارسال نشده است.
برای بازگشت کامل به رفتار قبلی، پرچم را false و پردازه را راه‌اندازی مجدد کنید؛ توجه:
این کار ممکن است پاسخ خودکار قدیمی را دوباره فعال کند. برای توقف همه AI، هم پرچم پایلوت
را false و هم `AI_ANSWER_ENABLED=false` تنظیم کنید.

## حریم خصوصی و محدودیت‌ها

UI پیش از تولید اعلام می‌کند متن اخیر به OpenAI فرستاده می‌شود. حذف الگوهای email،
شماره طولانی، Bearer و کلید API انجام می‌شود؛ **این ناشناس‌سازی کامل نیست**. نام، متن آزاد
یا اطلاعات حساس دیگر ممکن است باقی بماند. پیش از ورود داده واقعی، رضایت/مبنای پردازش،
سیاست نگهداری و قرارداد پردازش داده سازمان را بررسی کنید. برای پایلوت از داده ساختگی
استفاده کنید. نرخ/کارمزد، تراکنش مالی و تصمیم درمانی را مدل تعیین یا اجرا نمی‌کند.

خلاصه فقط بازه اخیر را پوشش می‌دهد، نه کل تاریخچه. خروجی و ویرایش‌ها فقط در بازبینی
مرورگر می‌مانند؛ ذخیره یادداشت داخلی در این نسخه اضافه نشده است. امتیاز کیفیت مدل و
صرفه‌جویی زمانی هنوز اندازه‌گیری نشده‌اند. بودجه روزانه در CRM پیاده نشده است.

## اعتبارسنجی

```sh
npm run test:ai-pilot --prefix backend
npm run build:dashboard --prefix backend
npm run quality
```

تست API: tenant isolation، احراز، ورودی نامعتبر، انتخاب صریح کلید، حذف شناسه‌ها، بازه
اخیر، نبود ارسال/تغییر پیام در تولید، توقف auto AI، حالت خاموش و rate limit.
تست UI: نیاز به اقدام تأیید، محتوای HTML مدل به‌صورت متن، خلاصه داخلی، نتیجه دیررس پس از
تعویض مکالمه، نبود کلید، پاک‌سازی نشست و ترجمه fa/en/tr. CI هم تست‌های پایلوت را اجرا می‌کند.

## استفاده از پارتنری

این قابلیت، ادغام API در محصول CRM است؛ مجوز فروش حساب ChatGPT/Claude یا کمک‌هزینه
پارتنری ایجاد نمی‌کند. ثبت فرصت/Deployment یا درخواست funding فقط با مشتری و دامنه
واقعی و شرایط برنامه مربوط انجام شود. هیچ ثبت پارتنری/مشتری یا ادعای تأمین مالی در این PR نیست.
